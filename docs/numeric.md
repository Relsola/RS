# 从点积到任务切换

在 `rs>` 输入 `run /numeric.elf`。这个磁盘程序用九对单精度数做点积，向两张匿名页写入四个整数，再派生一个子进程。下面是两台机器运行同一镜像的输出。

```text
numeric: dot = 165
numeric: exec cleared registers
child exit: 0
numeric: fork, timer and wait preserved registers
user exit: 0
```

## 向量循环为什么要读回 vl

前两个数组是 `1, 2, …, 9` 与 `9, 8, …, 1`。在自研 VM 上，每个向量寄存器有 128 位。程序选 `e32,m1`，一个寄存器容纳四个单精度数。三次 `vsetvli` 分别返回 4、4、1。每轮两条 `vle32.v` 载入元素，`vfmul.vv` 逐对相乘，`vfredosum.vs` 按顺序把积加入上一轮的和。结束时单精度和是 165，`fcvt.d.s` 转成双精度，按 LP64D 调用约定放进 `fa0` 返回给 C。[用户汇编](../OS/user/numeric.S) · [C 调用方](../OS/user/numeric.c)

`vlenb` 给出一个物理向量寄存器的字节数，`vl` 给出这次指令处理的元素数。元素宽度和分组保存在 `vtype`。例如 `e8,m8` 把八个连续寄存器当作一组，自研板可同时处理 128 个字节。采用分数组合 `e8,mf8` 时，一个寄存器只有低两个字节参与运算。RS 对不活动和尾部元素保留原值。程序要写得与宽度无关，每一轮都按返回的 `vl` 推进指针。同一个 ELF 在 256 位参考机上用两轮完成点积，在 512 位参考机上只需一轮。[分组布局](../VM/vector_state.h) · [V 1.0 规范](https://docs.riscv.org/reference/isa/v20240411/unpriv/v-st-ext.html)

## 为什么乘加不能拆成两条宿主运算

取双精度数 `a = 1 + 2⁻⁵²`、`b = 1 − 2⁻⁵²`。精确乘积是 `1 − 2⁻¹⁰⁴`。先把乘积舍入为双精度会得到 1，随后减 1 得到零。融合乘加 `fmadd.d` 要求保留精确乘积，再加上 −1，最终只舍入一次，因此结果是 `−2⁻¹⁰⁴`。这个例子也在指令测试里。[数值边界测试](../VM/tests/numeric_tests.cpp) · [D 扩展](https://docs.riscv.org/reference/isa/v20240411/unpriv/d-st-ext.html)

解释器把有限数拆成符号、整数有效数和二进制指数。乘法保留全部有效位，加法先按指数对齐。两个最小的 binary64 次正规数相乘，最低位可到 2⁻²¹⁴⁸。与最大有限数相加又要容纳高到 2¹⁰²³ 的位，因此教学实现给精确中间值预留固定长度的 32 位字数组。除法以余数记录后面是否还有非零位，开方每轮从被开方数取两位。它们最后共用舍入函数，按五种模式之一生成位串并累计 `fflags`。标量和向量浮点都走这条路径。[整数浮点运算与舍入](../VM/float_bits.cpp) · [F 扩展](https://docs.riscv.org/reference/isa/v20240411/unpriv/f-st-ext.html)

64 位浮点寄存器存单精度值时，高 32 位应全为 1。以单精度参与算术时，这些位缺失会得到规范的 quiet NaN。按位搬运和存储仍能保留原始低位及 NaN 载荷。Zfa 在这套表示上增加了立即数、安静比较、整值舍入和取低 32 位的模转换。向量的倒数估计 `vfrec7.v` 和倒数平方根估计 `vfrsqrt7.v` 有规定的七位结果，RS 用整数计算得到规范查表值。[标量译码](../VM/cpu_float.cpp) · [向量浮点](../VM/vector_float.cpp) · [Zfa 规范](https://docs.riscv.org/reference/isa/v20240411/unpriv/zfa.html)

## 一条写指令跨过两张未分配的页

`numeric_pages` 把目标指向第一页末尾前 8 字节，执行 `vse32.v` 写入 10、11、12、13。首次写入第 0 个元素时，内核给第一页分配页框。重试后前两个元素完成，第 2 个元素落到第二页，又触发写页故障。此时 `sepc` 仍指向这条向量指令，`stval` 指向第二页，`vstart=2`。内核补好第二页后，解释器从元素 2 接着执行，成功退休时清零 `vstart`。原生测试在重试前专门改写前一段 RAM，验证已完成的元素不会被重新读取。[向量访存](../VM/cpu_vector.cpp) · [缺页处理](../OS/kernel/paging.c) · [重试测试](../VM/tests/numeric_tests.cpp)

子进程随后往同一段地址写 −1，跨越的两张写时复制页分别拆分。父进程等它退出后，仍能读回原来的四个数。程序还在第二页的最后一个字执行 `vle32ff.v`。第 0 个元素成功，后面的地址不可读，此类加载按已完成的前缀把 `vl` 缩到 1。普通 `vle32.v` 在同样位置会报告异常。[用户程序的读写顺序](../OS/user/numeric.S) · [匿名虚拟内存](virtual-memory.md)

## 哪个任务拥有 hart 上的寄存器

内核 C 代码使用整数 ABI。独立汇编负责读写浮点和向量寄存器，内核用 `sstatus.FS/VS` 启用它们。每个任务保存 32 个浮点寄存器、`fcsr`、32 个向量寄存器和向量控制状态。向量数据区从内核栈上方的可用 RAM 分配，每个任务实际占 `32 × vlenb` 字节，自研板上是 512 字节。两个任务共用一颗 hart，`owner` 记录谁的值仍在硬件上。[现场布局与调度](../OS/kernel/context.c) · [内核内存布局](../OS/image.ld)

| 事件 | 内核处理 |
| --- | --- |
| 系统调用或缺页返回同一任务 | 内核只使用整数寄存器，用户的浮点与向量值留在 hart 上 |
| 定时器抢占或主动切到另一任务 | 保存旧任务，恢复新任务。先保存并清零 `vstart`，再用整组访存指令传输全部寄存器。恢复时最后写回 `vstart` |
| `fork` | 先从 hart 抓取父进程的最新值，再复制到子进程。父子从同一现场起步，此后分别保存 |
| `exec` 成功 | 清零新映像的寄存器与控制状态，设置 `vl=0`、`vtype.vill=1`。加载失败时，调用方继续使用原现场 |

程序还借用一个打开的文件验证抢占确实发生。父进程在四个时钟节拍内只读取时间，子进程在此期间从共享文件游标读走 `W`。父进程随后读到 `e`，并验证自己的寄存器值。这样，成功输出能同时证明子进程确实得到过时间片，以及父进程恢复了自己的扩展状态。[内核保存与恢复汇编](../OS/kernel/context.S) · [用户态验证](../OS/user/numeric.S)

## 复现指令对照

`ctest --preset debug -R "vm.numeric|boot.files" --output-on-failure` 可在自研 VM 上运行。给 CMake 设置 `RS_REFERENCE_QEMU` 后，`reference.numeric` 把两组由 Clang 汇编的探针放进一张临时盘，分别在自研 VM 和 128 位 QEMU 上运行。两边以相同数据比较每个探针的结果摘要，内容包括有效结果位和异常标志。掩码结果只比较有效位，归约只比较第零元素。编码和边界的抽样对照与完整 RVA23S64 的逐项验收分别记录。[对照脚本](../tests/numeric_reference.py) · [构建步骤](build.md) · [规范覆盖](rva23s64.md)
