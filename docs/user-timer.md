# 跟踪一个用户程序

在串口依次输入 `ticks`、`user`、`ticks`。中间会看到 `hello from user mode` 和 `user exit: 0`。用户程序先记下一个 tick，然后继续在 U 模式运行，直到下一次查询观察到计数增加。最后它通过系统调用输出一句话。沿着这段会话，可以读到 VM 的指令解释器、S 模式的中断处理函数和 U 模式的 C23 程序。[用户程序](../OS/user/demo.c) · [内核分派](../OS/kernel/trap.c) · [解释器入口](../VM/cpu.cpp)

## 从 shell 到用户地址

`user` 和 `tasks` 命令运行内嵌的教学程序。构建时先单独链接 `user.elf`，入口位于 `0x40000000`，代码和只读数据合计最多占一页。`user.bin` 只携带这部分内容，汇编器把它放进内核的一张 4 KiB 对齐页，并将页尾补零。用户可写的零初值对象放在单独的 `.bss` 页，由内核在每次启动任务时清零。固件从磁盘读内核时也读入了这份用户代码。[用户链接脚本](../OS/user/user.ld) · [镜像嵌入](../OS/user/embed.S)

另一条入口是 `run hello.elf`。这时内核从磁盘目录读取 ELF，在前台任务的页表中按程序头安装代码页和数据页，使用文件中的入口地址。两种程序遵循下文相同的系统调用约定。调试用户 PC 时，选择与命令对应的 `user.elf` 或 `hello.elf`。[从磁盘运行 ELF](disk-programs.md)

| 用户虚拟地址 | 页表授予 U 模式的权限 | 用途 |
| --- | --- | --- |
| `0x40000000–0x40000fff` | 读、执行 | 两个任务共享的入口、代码和常量字符串 |
| `0x40001000–0x40002fff` | 未映射 | 分隔代码和栈，越界会引发页故障 |
| `0x40003000–0x40003fff` | 读、写，禁止执行 | 每个任务独有的栈，初始 `sp=0x40004000`，向下增长 |
| `0x40004000–0x40004fff` | 未映射 | 分隔栈和可写数据 |
| `0x40005000–0x40005fff` | 读、写，禁止执行 | 每个任务独有的 `.bss`，存放零初值变量 |

shell 使用内核根页表。任务 A、B 各有自己的 Sv39 根页表，都包含内核 RAM 和设备的监管态映射（U 位为零）。内核启动双任务演示时安装上表的用户映射。两张用户根页表将代码的虚拟地址指向同一物理页，将栈和数据的虚拟地址分别指向各自的物理页。[页表构造](../OS/kernel/paging.c)

键入 `user` 只启动任务 A。内核清零它的用户栈和数据页，准备好第一份陷阱帧，其中 `sepc` 是入口，`sp` 是栈顶，`a0` 选择演示路径，`sstatus.SPP` 为 U。汇编入口在 shell 栈上保存调用现场，随后切换为 A 的根页表，从帧恢复寄存器并执行 `sret`。下次输入同一命令，这些用户状态会重新初始化。双任务命令使用相同的启动路径，额外准备 B 的地址空间和陷阱帧。[任务初始化](../OS/kernel/trap.c) · [进入与退出用户态](../OS/kernel/trap.S) · [双任务演示](tasks.md)

## 同一个陷阱入口怎样决定返回位置

| 触发者 | 硬件留下的线索 | 内核接下来做什么 |
| --- | --- | --- |
| U 程序执行 `ecall` | `scause=8`，`sepc` 指向这条调用指令 | 读取 `a7` 的调用号。可返回的调用把结果放入用户 `a0`，并将 `sepc` 加 4 |
| 定时器到期 | `scause` 最高位为 1，原因号为 5 | 更新计数及下一次期限，保留被打断处的 `sepc`。`tasks preempt` 下，若打断了 U 任务且另一任务可运行，先恢复另一任务 |
| U 程序首次读写已预留的匿名页 | `scause=13` 或 `15`，`stval` 是访问地址 | 分配零填充页框并安装叶项。成功时保持 `sepc` 原值，返回 U 模式重试同一条指令 |
| 父或子写入标记了写时复制的匿名页 | `scause=15`，页表项有效但 W 位为零 | 还有其他引用时复制页框，只剩一个引用时恢复写权限。成功后从原 `sepc` 重试 |
| U 程序读取受保护的 UART 页 | `scause=13`，`stval=0x10000000` | 打印原因、PC 和故障地址，终止当前任务。`user fault` 返回 shell，`tasks fault` 转去运行 B |

这些路径都会进入 `stvec` 指向的入口。硬件记录 PC 和少数状态位，入口汇编负责保存通用寄存器。U 运行时，`sscratch` 指向当前任务在内核中预留的 272 字节陷阱帧的末端。入口用 `csrrw` 交换 `sp` 和 `sscratch`，即使用户提供的 `sp` 无效，也能把它连同其他寄存器、`sepc` 和 `sstatus` 保存到任务自己的帧。随后 C 分派函数使用帧下方的私有 8 KiB 内核栈。S 运行时 `sscratch` 为零，入口就在被打断的 S 栈上分配陷阱帧。分派函数可以交还当前帧，也可以选中另一个 U 任务的帧。最后一个任务结束后，内核切回内核根页表，恢复 shell 的调用现场。[陷阱帧布局](../OS/kernel/trap.h) · [入口和返回汇编](../OS/kernel/trap.S)

### 用户可调用的内核服务

用户侧用 `a7` 传入调用号，按序用 `a0`、`a1`、`a2` 传入参数，在 `a0` 接收返回值。

| 调用 | 参数和结果 |
| --- | --- |
| `write`（1） | 用户缓冲区地址及长度。最多写 256 字节，成功时返回原始字节数，无效区间返回 `-1` |
| `ticks`（2） | 返回内核已处理的定时器 tick 数 |
| `exit`（3） | 以 `a0` 为状态码结束当前任务，内核打印状态码并运行剩余任务，整组结束后回到 shell |
| `yield`（4） | 主动让出 CPU，下次从 `ecall` 后一条指令恢复，返回值为 0 |
| `open`（5） | 路径地址及有效字节数。成功返回本任务的文件描述符，失败返回 `-1` |
| `read`（6） | 描述符、用户目的地址、请求字节数，单次上限 256。返回实际读取字节数，文件末尾返回 0，失败返回 `-1` |
| `close`（7） | 关闭指定描述符，成功返回 0，无效描述符返回 `-1` |
| `map`（8） | 按字节申请匿名区域，长度向上取整到 4 KiB。返回区域首地址，申请失败时返回空指针 |
| `unmap`（9） | 以申请时返回的首地址解除整段映射，成功返回 0，地址无效时返回 `-1` |
| `fork`（10） | 父进程得到正的子进程 ID，子进程得到 0。没有可用子槽或调用者无权创建子进程时返回 `-1` |
| `wait`（11） | 等待给定 ID 的子进程，返回其 32 位无符号退出码或故障结果 `-(256 + scause)`。无此子进程或已领取结果时返回 `-1` |

对于非空缓冲区，内核先验证整个地址区间，再逐页查调用任务的映射。已驻留页须具有用户读权限，向用户复制时还须具有写权限。遇到合法的匿名预留区时，内核检查页池余量并按需补页。复制按物理页分段进行，连续的虚拟页可以指向不同物理页。只有整段复制成功才写串口，所以第二页无权读取时，第一段也不会出现在屏幕上。[调用约定](../OS/user/abi.h) · [系统调用汇编](../OS/user/syscall.S) · [用户缓冲区检查](../OS/kernel/paging.c)

用两条命令就能观察跨页结果。`run hello.elf` 的一行问候从一个可写页的最后 8 字节开始，越过页界，输出成功。`user fault` 先验证跨入保护页和从最高地址开始的两个写请求均返回 `-1`，随后直接读取受保护的 UART 页，触发上表中的硬件页故障。[磁盘程序](../OS/user/hello.c) · [故障演示](../OS/user/demo.c)

`run memory.elf` 把文件读进跨页的匿名内存，同时经过路径解析、描述符和用户页表。观察 `cat /proc/meminfo` 可以区分用户态缺页重试和内核复制时补页这两条路径。[虚拟文件系统](vfs.md) · [按需分页](virtual-memory.md)

### 一个 tick 怎样到达内核

1. 固件在 M 模式设置 `menvcfg.STCE`、`mcounteren.TM`，允许 S 模式访问时间与比较值，并在 `mideleg` 中委托监管定时器中断。
2. 内核读取 `time`，把第一个期限写为 `stimecmp = time + 32768`，随后打开 `sie.STIE` 与 `sstatus.SIE`。
3. 自研 VM 每调用一次 `cpu_step` 将虚拟时间加一。若无符号的 `time >= stimecmp`，比较器令 STIP 待决。解释器在取下一条指令前检查使能位和当前特权级。决定投递时，这一步直接进入陷阱，下一条普通指令仍未执行。
4. 内核处理到期通知，增加计数并把下一次期限设为当前时间加 32768。关中断期间即使经过多个周期，内核也只为这次实际处理的到期事件计一次。屏幕上的 `ticks` 适合观察中断进展。它与宿主墙钟时间之间没有固定换算关系。

`stimecmp` 是比较阈值。内核处理后要把期限推到未来，否则从 `sret` 返回时，待决条件仍然成立。自研 VM 在每个指令边界检查这个条件。独立机器可能在写入新期限后短暂保留旧通知，内核通过比较当前时间与已登记期限避免重复计数。[VM 的比较器与中断路由](../VM/cpu_privilege.cpp) · [内核计时处理](../OS/kernel/trap.c) · [RISC-V Sstc 1.0](https://docs.riscv.org/reference/isa/v20250508/priv/sstc.html)

## 复现与定位

运行 `.\build.bat test` 可以复现 `boot.user`。用例在同一次启动中依次运行正常用户程序、故障演示、shell 的 `echo`，再运行一次正常用户程序。它核对两段计数进展、页故障的原因和地址，以及故障后仍能正常关机。同一会话也用于 QEMU 对照。[串口断言](../tests/user_session.py) · [VM 的边界测试](../VM/tests/cpu_tests.cpp)

想找到触发页故障的 C 代码，可以记下 `user fault` 输出的 `epc`，在带符号的用户镜像中查这个虚拟地址。

```powershell
llvm-objdump -d -S build/debug/images/user.elf
```
