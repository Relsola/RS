# 从虚拟磁盘启动到第一条命令

在项目根运行 `build.bat run`。看到 `rs> ` 时，CPU 已经执行过两个独立程序。固件在机器模式（M）下驱动磁盘，内核在监管模式（S）下建立页表并接管串口。输入 `echo hello`，可以沿着下面的路径追到终端上的第二个 `hello`。

| 阶段 | CPU 正在执行的代码 | 成功时可观察到的结果 |
| --- | --- | --- |
| 本机 VM 复位 | `0x1000` 处的只读复位代码 | PC 跳到 `0x80000000` |
| 读取磁盘 | `0x80000000` 起的 `firmware.bin` | 串口输出 `RS firmware: kernel verified` |
| 转交内核 | 固件执行 `mret`，从 `0x80200000` 开始执行内核 | 内核取得独立的栈和异常入口 |
| 建立地址空间 | 内核写入 `satp` 并检查读回值 | S 模式可通过设备的恒等映射重新初始化磁盘 |
| 挂载启动盘 | `fs_mount` 读第 0 扇区，按其中的标记查找只读文件目录 | 出现 `rs>` 后用 `ls` 查看根目录。在只含内核的旧盘上，根目录仍有 `proc/`。RSFS 目录损坏时，访问磁盘文件会报告错误，`cat /proc/meminfo` 仍可用 |

VM 启动时把固件复制到 128 MiB RAM 的最低地址，另把磁盘镜像以只读方式挂在块设备上。固件提交扇区读取请求后，内核字节才进入 RAM。`user` 和 `tasks` 所用的用户程序作为内核中的一张只读页随内核装入。`run hello.elf` 从启动盘另读一个独立文件，由内核解析其中的程序头。查找这四个程序的符号时，分别使用 `firmware.elf`、`kernel.elf`、`user.elf` 和 `hello.elf`。[宿主装载入口](../VM/main.cpp) · [复位 ROM](../VM/bus.cpp) · [来宾构建](../OS/CMakeLists.txt)

用 `llvm-objdump -d` 分别查看固件和内核 ELF，固件反汇编中的相邻指令地址相差 4，内核则混合 2 字节与 4 字节的指令。Clang 为内核启用了 C 压缩扩展。VM 根据首个半字决定长度，将压缩指令展开成对应的整数编码后复用执行逻辑。例如 `c.jalr` 展开成跳转并链接指令，写入链接寄存器的返回地址仍是原始 PC 加 2。[压缩指令展开](../VM/cpu_compressed.cpp) · [取指与执行](../VM/cpu.cpp)

## 磁盘上有哪些字节

扇区固定为 512 字节。直接查看镜像开头，应该能读到 ASCII 文本 `RSDISK01`。这是 RS 约定的启动盘格式。

| 镜像字节偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 8 字节 | `RSDISK01`，连续八字节 |
| 8 | 4 字节 | 内核裸二进制的有效字节数，小端无符号整数 |
| 12 | 4 字节 | 有效字节的 IEEE CRC32，小端无符号整数 |
| 16 | 8 字节 | 带文件目录的镜像写入 `RSFS0001`。旧版只含内核的镜像在此填零 |
| 24 | 488 字节 | 保留区，制盘工具填零 |
| 512 | 按扇区取整 | 从第 1 扇区起连续存放内核，末扇区尾部填零 |

例如 1200 字节的内核占用三个数据扇区。固件向 `0x80200000` 连续读入 1536 字节，CRC 只计算前 1200 字节。固件先验证魔数和大小（1 字节至 8 MiB），再比较所需扇区数与设备报告的容量，最后核对 CRC。入口地址由内核链接配置和固件共同约定。[制盘程序](../tools/mkdisk.py) · [固件读取与校验](../OS/boot/firmware.c)

对于带文件的镜像，紧跟内核末扇区的是一整个目录扇区，编号为 `1 + ceil(内核字节数 / 512)`。上例的目录在第 4 扇区，文件数据从第 5 扇区起存放。下表的偏移相对于**目录扇区**，整数均采用小端格式。

| 目录内偏移 | 内容 |
| --- | --- |
| 0 至 7 | 魔数 `RSFS0001` |
| 8 至 11 | 目录第 12 至 511 字节的 CRC32，覆盖计数、保留区和全部文件项 |
| 12 至 31 | 前 4 字节为文件数量，后 16 字节保留并填零 |
| 32 至 511 | 最多 15 项，每项 32 字节。前 20 字节保存以零结束并填充的 ASCII 名称，后面依次为 4 字节的绝对起始扇区号、有效字节数、文件 CRC32。未使用的项填零 |

每个文件占据一段连续扇区，末扇区可填零，文件 CRC 只计算有效字节。内核在挂载时校验整张目录的 CRC、名称、范围与重叠关系，读取某个文件时才检查该文件的 CRC。因而一个文件内容损坏，其他完好文件仍可以读取。RSFS 使用单层目录，单文件上限为 64 KiB。[内核只读文件系统](../OS/kernel/fs.c) · [磁盘文件与程序装载](disk-programs.md)

## 一次扇区读取如何完成

固件从 `0x10001000` 开始探测八个相隔 4 KiB 的 MMIO 插槽，寻找设备类型为 2 的现代 virtio-blk 设备。驱动复位设备，依次置位 `ACKNOWLEDGE` 和 `DRIVER`，协商 `VIRTIO_F_VERSION_1` 及设备提供的只读特性，再写入并读回 `FEATURES_OK`。双方认可特性后，驱动选择队列 0，设置长度为 8，交给设备三块来宾 RAM 的物理地址，分别存放描述符表、可用环和完成环。队列就绪后置位 `DRIVER_OK`。[来宾驱动](../OS/boot/disk.c) · [VM 块设备](../VM/virtio.cpp)

每次读操作只占用一条描述符链，链首的编号总是 0。

| 描述符 | RAM 中的内容 | 设备如何使用 |
| --- | --- | --- |
| 0 | 16 字节请求头，含读取类型及 64 位扇区号 | 读取头部，跟随 `next` 到 1 |
| 1 | 512 字节目标缓冲区 | 写入数据，跟随 `next` 到 2 |
| 2 | 1 字节完成状态 | 写入状态，结束本链 |

描述符的 `WRITE` 从**设备**的视角定义。因此读磁盘时，目标缓冲区和状态字节都带 `WRITE`。驱动把链首编号放入可用环，执行 `fence iorw, iorw`，再递增可用索引。第二次屏障保证索引先于 MMIO 通知对设备可见。设备处理后更新完成环，驱动观察到完成索引前进，再经过屏障读取结果。一次成功读取应对应链首 0、写入长度 513 和状态 0。两个环各自持有递增的 16 位索引，只有选择数组槽位时才对 8 取模。[设备处理请求的代码](../VM/virtio.cpp) · [OASIS Virtio 规范，第 2.7、4.2、5.2 节](https://docs.oasis-open.org/virtio/virtio/v1.3/virtio-v1.3.html)

## 内核如何接管机器

1. **准备 C 运行环境。** 固件和内核各自链接同一份入口汇编。每次进入 `_start` 都把 `sp` 设为该镜像 32 KiB 栈的顶端，设置当前模式的异常入口，再按链接器给出的边界清零 `.bss`。磁盘上的内核只需携带有初值的内容。[入口汇编](../OS/entry.S) · [链接脚本](../OS/image.ld)
2. **从 M 进入 S。** 固件校验内核后设置物理内存保护（PMP），允许 S 模式访问本板 RAM 和设备。它再通过 `medeleg` 把常见同步异常委托给 S 模式，将 `satp` 清零，以物理地址作为内核的起点。最后设置 `mstatus.MPP=S` 与 `mepc=0x80200000`，执行 `fence.i` 同步新装入的指令，再执行 `mret`。此次返回同时改变 PC 和特权级。[固件交接](../OS/entry.S)
3. **打开 Sv39。** 内核准备三张根页表，先启用 shell 的那张。128 MiB RAM 大部分由 2 MiB 叶项恒等映射。文件缓存所在的 2 MiB 使用末级页表，为缓存单独建立不可执行的 64 KiB Svnapot 映射，其余部分使用普通 4 KiB 页。关机寄存器、UART 和 virtio 插槽也各有监管态读写页。内核将根页表的物理页号写入 `satp`，设置模式 8 和 ASID 0，写入前后各执行一次 `sfence.vma x0, x0`。切换后的下一条指令和当前栈仍可通过恒等映射访问。[页表构造](../OS/kernel/paging.c) · [文件缓存映射](svnapot.md) · [切换汇编](../OS/entry.S)
4. **在 S 模式接管磁盘。** 固件与内核分别链接同一个 `boot/disk.c`。内核重新探测并复位设备，把自己的队列索引归零，再把自己的描述符表和环地址注册给设备。由于内核 RAM 使用恒等映射，这些指针的数值就是 DMA 所需的物理地址。此后，磁盘文件的扇区读取使用内核缓冲区。VFS 还在 `/proc` 提供内核生成的文件，读它们只需访问内存。挂载结束后，内核启动定时器并显示提示符。[块驱动](../OS/boot/disk.c) · [挂载与文件读取](../OS/kernel/fs.c) · [shell 入口](../OS/kernel/shell.c)

另外两张根页表留给任务 A 和 B，均复用内核的监管态映射。输入 `user` 或 `tasks` 的子命令后，内核准备内置程序的共享只读代码页和各任务的私有可写页。输入 `run hello.elf` 时，内核在第一个任务槽中为磁盘 ELF 的装载段设置页权限。两种入口都切换到选定的任务根页表，通过 `sret` 首次进入 U 模式。启动时预留的匿名页框池供任务按需使用。在 `tasks memory` 或 `run memory.elf` 中，首次访问已申请的虚拟页才会安装相应的用户叶项。[跟踪一个用户程序](user-timer.md) · [双任务调度](tasks.md) · [磁盘文件与程序装载](disk-programs.md)

## 一个字符如何往返

输入 `echo hello` 时，VM 的串口把宿主终端输入呈现为 UART 接收数据。内核轮询 `0x10000005` 处线路状态寄存器的位 0，发现数据就绪后从 `0x10000000` 读取一字节。Shell 将其加入行缓冲并逐字回显。按下回车才会解析命令。此时出现的第二个 `hello` 是 `echo` 的执行结果。输出方向上，内核等待同一状态寄存器的位 5，再向数据端口写一字节，VM 将它送回宿主终端。[宿主终端](../VM/console.cpp) · [UART 寄存器](../VM/bus.cpp) · [来宾串口驱动](../OS/platform.c) · [行编辑与命令](../OS/kernel/shell.c)

Shell 接受 CR、LF 和 CRLF，Backspace 或 DEL 可以退回一个字符。一行最多保存 127 个字符，超过上限就丢弃整行并提示 `line too long`。可以用 `info` 查看内核模式和启动设备，再输入 `halt`，由 S 模式向 `0x00100000` 写入关机值。

## 从最后一条消息定位故障

| 屏幕消息或现象 | 优先检查 |
| --- | --- |
| 宿主提示 `Disk must be a readable image of whole 512-byte sectors` | 镜像路径、文件长度及扇区对齐。此时 CPU 尚未开始执行 |
| `boot error: virtio-blk unavailable` | 块设备挂载、MMIO 传输版本、特性握手和队列创建 |
| `invalid disk magic` 或 `invalid kernel size` | 第 0 扇区的前 12 字节 |
| `truncated kernel` | 头部声称的内核大小是否超过盘上实际数据 |
| `kernel CRC mismatch` | 头部偏移 12 的校验值与第 1 扇区开始的有效载荷 |
| `ls: invalid directory` | 检查第 0 扇区的扩展标记、目录扇区位置及 CRC，再核对每项的文件范围、重名或重叠 |
| `cat: file CRC mismatch` 或 `run: file CRC mismatch` | 按文件项的起始扇区和有效长度计算 CRC，与该项最后 4 字节比较 |
| `M trap` 或 `S trap` | 按特权级选 `firmware.elf` 或 `kernel.elf`，对照异常原因、`epc` 处的指令以及 `tval` |
| `user fault: cause=13` 或 `task A fault: cause=13` | 用 `user.elf` 查 `epc` 处的指令。`tval=0x10000000` 对应受保护的 UART。单任务演示回到 shell，双任务演示继续执行 B |
| `kernel error: Sv39 unavailable` | CPU 对写入 `satp` 的模式、根页表地址的支持 |

端到端测试会生成魔数错误、CRC 错误和内容截断的临时镜像，检查串口诊断和退出状态。正常用例还覆盖退格、超长命令后的恢复及关机。[启动回归测试](../tests/boot.py)
