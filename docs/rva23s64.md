# RVA23S64 目标与当前能力

RVA23S64 规定 64 位应用处理器给监管模式软件提供的整组行为，还包含 RVA23U64 的必选能力。RS 以该规范安排自研路线，当前版本交付一台可从磁盘启动的教学用 RV64 机器。普通构建的测试结果反映下表中的实现范围。完整 Profile 仍有必选项待开发和验证。[RISC-V International · RVA23 Profiles 1.0](https://docs.riscv.org/reference/rva23/v1.0/rva23-profiles.html)

| 范围 | 当前实现 | 怎么验证或观察 |
| --- | --- | --- |
| 整数与指令长度 | RV64I、M、整数压缩指令及 Zcb、标量位操作 Zba/Zbb/Zbs、条件清零 Zicond、Zicsr、Zifencei | 单测覆盖指令边界、编码与展开、目标寄存器重叠、访存结果和异常 PC |
| 原子操作 | RV64 A 2.1 的 LR/SC 和九类 AMO，支持自然对齐的 32 位和 64 位 RAM 操作。单 hart 按序执行，保留集按物理字节跟踪 | 指令用例检查运算及读回值、权限、保留失效和重试。设备测试单独检查 DMA 写入 |
| 特权级与异常 | M/S/U，关键 CSR，异常委托，直接陷阱入口，MRET/SRET，PMP | 固件在 M 模式设好权限并进入 S。单测从 U 触发异常、再从 S 返回 |
| 地址翻译 | Bare、Sv39 三级遍历、页访问权限、A/D 缺失异常、普通 RAM 错位访问 | 实际内核打开页表。单测使用非恒等映射及跨页失败访问 |
| 计时与中断 | cycle/time/instret 计数，Sstc 监管定时器比较、CSR 门控和特权级中断投递（单 hart，无 H 扩展） | VM 测试检查在指令边界进入中断、重设与返回。OS 的 `ticks` 显示已处理次数 |
| 学习板外设 | 一颗 hart、只读复位 ROM、128 MiB RAM、轮询串口、只读 virtio 块设备、关机寄存器 | 磁盘正反例与命令行端到端用例。可选 QEMU 对照 |
| OS | 自编固件、S 模式串口 shell、两个固定 U 任务。任务共享只读代码，各有 Sv39 根表、可写数据页、用户栈和内核栈 | `tasks yield`、`tasks preempt`、`tasks fault` 分别验证主动让出、定时器抢占和单任务故障恢复 |
| 磁盘程序 | RSFS 只读平面目录、静态 ELF64 加载、独立的用户代码页与可写数据页 | `run hello.elf` 从磁盘装入程序，实际执行 Zcb 和 Zicond，再通过跨页缓冲区输出文字 |
| OS 文件与内存管理 | 只读 VFS 挂载 RSFS 和 procfs。每个任务有自己的打开文件表及匿名虚拟地址区间，首次访问分配零页 | `run /memory.elf` 读取文件到跨页匿名缓冲区。`tasks memory` 验证任务间数据和读偏移互相独立 |

设备地址、磁盘头和固件进入内核的约定属于本板设计。Profile 规定处理器的软件接口，镜像格式由固件与制盘工具共同约定。测试分开观察这两层行为。[启动协议与磁盘布局](boot.md)

## 完整验收还差什么

以下按机制列出主要差距。正式验收时须逐项核对官方必选清单里的版本、指令、CSR、异常与内存属性，覆盖边界和组合行为。

| 规范中的机制 | 仍待实现或单独验证的例子 |
| --- | --- |
| 内存模型与平台属性 | 平台内存属性、错位原子性以及规范要求的前进性仍需逐项核对。当前测试覆盖单 hart 及其同步设备 |
| 浮点与向量 | F、D、Zfhmin、Zfa、V、Zvfhmin、Zvbb、Zvkt，以及浮点状态和向量状态的保存 |
| 额外整数和系统扩展 | Zimop、Zcmop、Zawrs、相应提示和附加约束 |
| 缓存、时序及性能事件 | 缓存块大小与操作、Zkt、硬件性能监视和 Sscofpmf |
| 监管层的附加能力 | Svpbmt、Svinval、Svnapot、指针屏蔽和完整的特权架构行为 |
| 虚拟化 | Sha 所含 H 扩展及附加要求，例如 VS/VU 上下文、两阶段地址翻译和虚拟陷阱信息 |

要把处理器机制与 OS 联系起来，可以先在 `tasks preempt` 观察保存的用户 PC，再看调度器怎样切换页表，以及为什么在恢复下一任务前执行一次 `sc.d`。[单核上的两个用户任务](tasks.md) · [原子指令与保留集](atomics.md)

将同一镜像交给 QEMU 的 `rva23s64` 型号，能对照引导协议、设备驱动与内核的可移植性。完整合规性需要独立的逐项验证。怎样复现本项目的对照测试见[构建与验证](build.md)。
