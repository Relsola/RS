# 跟踪一次 fork 和 wait

在 `rs>` 输入 `run /family.elf`。下面四行来自一次父子进程会话。前两行由子进程和内核依次打印，接下来才轮到父进程打印自己的结果。[磁盘程序](../OS/user/family.c)

```text
child: page=C file=_
child exit: 37
parent: page=P file=p wait=37
user exit: 0
```

## 从同一个调用点走出两条路径

程序先打开 `/proc/meminfo`，读走开头的四个字符 `pool`，再向自己的匿名页写入 `P`。执行到 `long child = user_fork();` 时，父子随后要用到的内存和文件都已有内容。

CPU 执行 `ecall` 进入内核。分派器将陷阱帧中的 `sepc` 加 4，再把这份寄存器现场复制给子进程。子帧里的 `a0` 设为 0，父帧里的 `a0` 得到正的子进程 ID。两边从同一个地址继续，C 程序的 `if (child == 0)` 因而走向两个分支。单颗 hart 上的定时器可以让这两个分支交替执行。父进程调用 `user_wait(child)`，保证它的输出排在子进程退出之后。[系统调用与调度](../OS/kernel/trap.c) · [等待与退出顺序](tasks.md)

## 一页内存和一个打开文件怎样变化

文件开头是 `pool_pages`。下面的偏移从 0 起算，表示下一次读取的位置。页框数只统计示例的那一页匿名内存。

| 程序运行到哪里 | 匿名页的内容和物理页框 | 文件偏移 |
| --- | --- | --- |
| 父进程准备好数据 | 父读到 `P`，占一个页框 | 4，下一个字符是 `_` |
| `fork` 返回 | 父、子都读到 `P`，两份只读映射指向一个页框 | 4，两张描述符表引用同一个打开文件 |
| 子进程写入 `C`，读一个字节并关闭描述符 | 子读到 `C`，父仍能读到 `P`，共两个页框 | 5，父进程仍持有这个打开文件 |
| 子进程以 37 退出，父进程从 `wait` 返回 | 子的页框已释放，父仍读到 `P` | 父读出 `p`，偏移推进到 6 |

在子进程执行 `*page = 'C'` 时，原来的页表项已经撤掉写权限。VM 产生写页故障，内核查到写时复制标记，才给子进程分配页框并复制内容。返回时保留这条写指令的 `sepc`，让 CPU 用新的映射重试。程序还改写了栈变量和 ELF 的可写全局变量。它们使用在 `fork` 时直接复制的固定页，也会保留各自的值。[页表与页框算法](virtual-memory.md)

两次读文件经过的是另一条路径。父子在各自的描述符表中找到同一个打开文件对象，偏移保存在这个对象里。子进程读到的 `_` 和父进程读到的 `p` 恰好相邻。运行 `tasks memory` 可以做另一个实验，两个任务分别打开同一路径，这时各自从偏移 0 开始。[描述符与打开文件](vfs.md)

## 继续读代码时可以验证什么

默认盘适合逐行对照输出。回归测试另外编译小型磁盘 ELF，构造示例之外的条件。例如向共享页执行 `amoadd.w`，重试后只能加一次。又如让一次 `read` 横跨两个共享页，但页池只剩一个空闲页框，调用必须返回 `-1`，两个字节和文件游标都留在原处。运行 `.\build.bat test`，或已构建后运行 `ctest --preset debug -R disk.fork --output-on-failure`，即可复现。[专项测试](../tests/fork_tests.py) · [构建与验证](build.md)
