# 跟一次磁盘读取，看 CPU 与设备怎样交接缓冲区

从一张新启动的标准盘开始，依次输入下面的命令。第一次读 `/proc/diskstats` 时，内核已经读过启动头和 RSFS 目录，所以请求数和扇区数都是 2。固件有自己的驱动实例，读取内核的请求计在固件这一侧。

```text
rs> cat /proc/diskstats
rs> run hello.elf
rs> cat /proc/diskstats
rs> run hello.elf
rs> cat /proc/diskstats
```

本次构建的 `hello.elf` 占 29 个磁盘扇区。第一次运行后，请求数从 2 增至 6，成功读取的扇区数从 2 增至 31。驱动提交了四批，大小依次为 8、8、8、5 个扇区。再次运行后再读统计，数值相同，因为 RSFS 仍持有这个文件的已校验副本。其他构建的 ELF 大小可从 `ls` 读取，扇区数等于文件字节数除以 512 后向上取整。[RSFS 文件缓存](../OS/kernel/fs.c) · [驱动计数器](../OS/boot/disk.c) · [procfs 快照](../OS/kernel/procfs.c)

## 为什么读 4 KiB 会收到完成长度 4097

一批最多 8 个连续扇区，即 4096 字节。固件装入内核和 RSFS 填充文件缓存都走 `disk_read_sectors`。它先比较整个范围与磁盘容量，再逐批提交。每一批只占用三个描述符，设备读请求头，写目标缓冲区，最后写一个状态字节。因此成功的 `used.len` 是 `512 × 扇区数 + 1`。文件尾不足一扇区时，驱动仍接收完整扇区，RSFS 按目录记录的实际文件长度计算 CRC。[来宾块驱动](../OS/boot/disk.c) · [OASIS Virtio 1.3，第 2.7 和 5.2 节](https://docs.oasis-open.org/virtio/virtio/v1.3/virtio-v1.3.html)

队列长度也恰好是 8，它表示环上可存放的条目数，与每批扇区数独立。RS 每次等待一个请求完成，再复用描述符。读满 64 KiB 文件会提交 16 批，环槽位循环使用两遍。完成环中的条目从第 4 字节开始，每项 8 字节，第 7 号槽覆盖偏移 60 到 67，横跨两个 64 字节缓存块。维护一个范围时必须处理它碰到的**所有块**。[完成环布局](../OS/boot/disk.c) · [缓存块范围遍历](../OS/entry.S) · [磁盘回归](../tests/block_io_tests.py)

## 一块内存什么时候归设备写

| 时刻 | 驱动在做什么 | 对缓存和顺序的要求 |
| --- | --- | --- |
| 准备 | CPU 填写请求头、描述符、可用环槽和初始状态 | 对设备将读取的块执行 `cbo.clean`。对设备将写入的状态和数据区执行 `cbo.flush`，把旧脏数据写回并移除缓存副本 |
| 发布 | CPU 推进可用索引，再写 MMIO 通知寄存器 | 用 `fence iorw, iorw` 排好描述符、索引与通知的顺序。索引所在块在更新后再 clean 一次 |
| 等待 | CPU 轮询设备写入的完成索引 | 每次轮询先使索引所在块失效，经过屏障再读。观察到新索引后，再取得对应的完成条目 |
| 收回 | CPU 读取完成条目、状态和数据 | 对相应范围执行 `cbo.inval`，并用屏障排序后续读取。链首、完成长度和状态都匹配，才把本批计入成功扇区数 |

CPU 执行失效指令时会影响整个块。如果可用环和完成环共用一块，设备更新完成索引的同时，CPU 写回可用环就可能覆盖它。`DmaQueue` 的成员分别按 64 字节对齐，结构体尾部也有填充，数据区由调用者独占到请求完成。自研 VM 的 CPU 与设备直接访问同一份 RAM，因此两者天然看见同一份数据。该模型可以验证指令权限、队列顺序和最终字节；带独立缓存的非一致性硬件仍需实机验证。[DMA 队列](../OS/boot/disk.c) · [缓存管理指令](cache-blocks.md) · [VM 总线](../VM/bus.cpp)

## 失败的批次怎样计数

`read_requests` 计已提交的读取请求，`read_sectors` 只计完整成功的批次，`read_errors` 计设备读取失败的批次。读取 `/proc/diskstats` 会在打开时固定一份快照；同一描述符可以分段读，重新打开才看到新数值。文件 CRC 是设备读取完成后由 RSFS 检查的，校验失败与驱动读错误可分别观察。[快照接口](vfs.md)

原生回归先启动临时测试盘，再缩短测试镜像，让一个 128 扇区文件只剩前 11 个扇区可读。第一批完整读到 8 个扇区，第二批只收到 3 个扇区和错误状态。两次请求令三个计数分别增加 2、8、1，shell 报告 `file read failed`。RSFS 在开始 DMA 前已撤掉旧缓存标签，之后仍能重新读取盘中完好的程序。[短读与缓存回收测试](../tests/block_io_tests.py)
