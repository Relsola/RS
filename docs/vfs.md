# 一个路径如何找到磁盘或内存里的文件

在 `rs>` 输入 `cat /readme.txt` 和 `cat /proc/meminfo`。第一条命令通过块设备读出制盘时写入的字节。第二条命令让内核把此刻的虚拟内存统计格式化为文本。两条命令都经过同一个 `vfs_open`，用同一个 `vfs_read` 循环读到文件末尾。这个为多种数据来源提供统一文件接口的内核层就是虚拟文件系统（VFS）。[shell 调用方](../OS/kernel/shell.c) · [VFS 接口](../OS/kernel/vfs.h)

## 路径经过哪些目录

运行 `ls /` 可看到磁盘文件和挂载目录 `proc/`，`ls /proc` 可看到 `meminfo`。启动时，内核从静态挂载表安装两个后端。RSFS 提供根目录 `/`，procfs 提供根的一个直接子目录 `/proc`。两者分别实现目录查找、枚举、打开文件和取得内容的操作。增加一个只读后端时，可以实现同一组回调，再为它登记一个挂载点。[挂载表和路径遍历](../OS/kernel/vfs.c) · [后端接口](../OS/kernel/vfs_internal.h)

以下命令能区分“逐个访问路径组件”和“先把路径当字符串化简”这两种行为。

| 在 shell 输入 | 发生什么 |
| --- | --- |
| `cat //proc/./../readme.txt` | 从根进入 procfs，跳过 `.`，用 `..` 回到根，向 RSFS 查找 `readme.txt` |
| `cat ../../readme.txt` | 本板的相对路径从根开始，连续的 `..` 在根处停留 |
| `cat readme.txt/../readme.txt` | 报告 `not a directory`。查到第一个普通文件后，无法继续向下遍历 |
| `cat missing/../readme.txt` | 在查找 `missing` 时就报告 `file not found` |

挂载点优先于所在目录的同名条目。即使一张盘里有普通文件 `proc`，在这台机器上访问 `/proc` 时也会进入 procfs。根目录枚举同样遵守这个规则，只列出一次 `proc/`。旧盘只含内核时，磁盘文件列表为空，`/proc` 仍可使用。挂载 RSFS 时发现目录损坏会保留原诊断，已经安装的 procfs 有自己的查找路径。[磁盘格式](disk-programs.md)

## 两次打开，一个缓存

设用户程序两次打开 `/readme.txt`，分别得到描述符 3 和 4。从 3 读取两个字节得到 `We`，再从 4 读取两个字节，仍会得到 `We`。此时下一次从 3 读取会从 `l` 开始。偏移量属于每个打开的 `VfsFile`。描述符是任务自身表中的编号，另一个任务的编号 3 可以引用它自己打开的文件。

`fork` 复制描述符表里的引用。父子各自的描述符 3 指向同一个打开文件对象，其中保存读取偏移和 procfs 在打开时生成的文本。子进程读一个字节会推进两者共用的游标，随后关闭自己的描述符只会减少一次引用。最后一个持有者关闭它或退出时，内核回收这个打开文件对象。系统有八个对象槽，足够两个进程各自打开四个文件。[描述符实现](../OS/kernel/user_files.c) · [父子共同读一个文件的例子](fork.md)

RSFS 首次提供文件字节时会按扇区载入文件、检查 CRC，然后给共享的只读缓冲区标记当前文件。连续短读可以复用这一缓冲区。交替读取两个磁盘文件时，缓冲区可以反复换内容，两个描述符的偏移分别保留。DMA 开始前需要先清除旧标签，因为一次失败的读取也可能已经覆盖了缓冲区的前半部分。[RSFS 与缓存](../OS/kernel/fs.c)

一个任务最多同时打开 4 个文件，描述符为 3 至 6。`open(path, length)` 复制给定长度的路径，最多 127 字节。`read(fd, address, count)` 每次最多请求 256 字节，到 EOF 返回 0。内核先读文件，再按调用任务的页表把字节拷入用户缓冲区。如果第二步失败，系统调用返回 `-1` 并还原偏移，再次读取仍从原处开始。`close(fd)` 和任务退出都会释放描述符槽。[用户描述符](../OS/kernel/user_files.c) · [系统调用编号](../OS/user/abi.h)

## 为什么 /proc/meminfo 在打开时统计

procfs 在 `open` 时调用 `vm_stats()`，将四行十进制文本放入该次打开的句柄。进程可以先读一行，申请或触碰若干新页，再读剩下的行。整份内容仍来自打开时的同一时刻。要看变化，再次打开同一路径即可。

| 字段 | 含义 |
| --- | --- |
| `pool_pages` | 所有任务共享的匿名物理页池容量，以 4 KiB 页计 |
| `resident_pages` | 当前占用的匿名物理页框数。父子同时映射同一个页框时只计一次 |
| `reserved_pages` | 任务已经保留的匿名虚拟页总数，包含已分配物理页的部分 |
| `faults` | 开机以来，内核成功处理的用户指令匿名缺页次数。系统调用主动为用户缓冲区准备页不计入此项 |

当前 VFS 提供只读操作，挂载点位于根目录下。磁盘格式本身仍是单层 RSFS。可以先查看 `cat /proc/meminfo`，再运行 `run /memory.elf`，让用户程序通过文件描述符把文件读入匿名内存。程序退出后再次查看统计，可以看到累计缺页次数增加，驻留页数恢复到原值。[procfs 后端](../OS/kernel/procfs.c) · [页状态与补页](../OS/kernel/paging.c)
