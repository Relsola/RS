# Svnapot 如何用 16 个末级表项描述 64 KiB

以测试中的映射为例，内核希望让一段连续的用户虚拟地址 `0x40010000–0x4001ffff` 指向物理地址 `0x80030000–0x8003ffff`。两端都按 64 KiB 对齐。Sv39 通常需要 16 个 4 KiB 叶项，每项的物理页号递增。Svnapot 1.0 让这 16 项可以填写同一个编码，硬件因而可以用一个地址翻译缓存项覆盖整段。[Svnapot 1.0 规范与编码表](https://docs.riscv.org/reference/isa/v20240411/priv/svnapot.html)

## 手算一个地址

要从虚拟地址 `0x40015abc` 取一个字节，可以按下面的步骤走一遍 VM 的 Sv39 遍历。

1. 按 VPN 的三个 9 位索引依次查表。这里三个索引分别为 `1`、`0`、`0x15`，所以最终读到末级表的第 `0x15` 项。这个位置处在第 `0x10` 到 `0x1f` 项的连续范围内。
2. 读出叶项。最高位 N 为 1，编码的物理页号 PPN 是 `0x80038`。这个页号的低四位 `1000` 表示 64 KiB 范围。
3. 将编码 PPN 的低四位替换为虚拟页号的低四位 `5`，得到实际 PPN `0x80035`。拼上页内偏移 `0xabc`，得物理字节地址 `0x80035abc`。这次替换只作用于本次翻译，内存里的 PTE 保持原样。[页表遍历实现](../VM/cpu_mmu.cpp)

| N | 页表层级与 PPN | 翻译 |
| --- | --- | --- |
| 0 | 末级，PPN 为 `0x80038` | 普通 4 KiB 页，同一个虚拟地址译成 `0x80038abc` |
| 1 | 末级叶项，PPN 为 `0x80038` | 64 KiB 连续区域，译成 `0x80035abc` |
| 1 | 末级叶项，PPN 低四位取其他值，或使用上层叶项 | 保留编码，按原始访问类型产生页故障 |

## 为什么要填写 16 项

解释器每次都从 `satp` 指定的根表重新遍历，只读取这次虚拟地址选中的末级项。带 TLB 的处理器也可以从某一个 NAPOT 项缓存同一范围中其他页的翻译。要让同一份页表在两者上具有一致的含义，操作系统应将整组项指向相同的范围，并保持权限一致。若替换整个映射，应先使旧项失效，再对涉及的 16 个基页同步翻译，或者执行一次覆盖整个地址空间的同步。[Svnapot 缓存与更新规则](https://docs.riscv.org/reference/isa/v20240411/priv/svnapot.html)

N 位只改变物理页号的来源。U、R、W、X 权限照常生效。VM 遵循 Svade，访问 A 为零的项或写入 D 为零的项会产生页故障，翻译成功之后还会检查物理地址的 PMP 权限。测试给 16 个基页各写入一条不同的指令，再通过连续虚拟地址逐页执行。如果忘记替换 PPN 的低四位，每次都会读到同一条指令。可用 `ctest --preset debug -R vm.svnapot --output-on-failure` 复现。[Svnapot 测试](../VM/tests/napot_tests.cpp) · [Sv39 与 PMP](privilege-memory.md)

## 在 OS 中找到同一种映射

在 shell 输入 `cat /readme.txt`，磁盘驱动把文件读入 RSFS 的 64 KiB 缓存，随后内核从缓存中取字节。缓存按 64 KiB 对齐，内核为它填写 16 个相同的末级项，授予监管态读写权限，并清除执行位和用户位。这里的映射是恒等映射，CPU 使用 Svnapot 翻译后得到原物理地址，virtio 设备继续使用描述符中的物理地址执行 DMA。上例特意让虚实地址不同，便于在测试中识别页号拼接错误。[文件缓存](../OS/kernel/fs.c) · [内核页表](../OS/kernel/paging.c)

整机测试 `disk.rsfs` 会换上一份恰好 65536 字节的 ELF，16 个 4 KiB 块各有自己的填充值。RSFS 先核对整份文件的 CRC，加载器再从开头解析 ELF 头，从文件尾取出以 `ecall` 结束的 12 字节程序。若从磁盘到缓存再到用户态的每一步都正确，串口会打印 `user exit: 37`。[最大文件的启动测试](../tests/rsfs_tests.py)
