# 一个进程怎样换成另一个程序

在 `rs>` 输入 `run /launch.elf`。启动程序调用 `user_fork()`，让子进程执行 `user_exec("/hello.elf", 10)`，父进程在原来的程序里调用 `user_wait(child)`。子进程接下来执行磁盘中 `hello.elf` 的入口，输出问候语并退出。父进程领到新程序的退出码 0，于是打印 `launch: child completed`。子进程 ID 从创建到退出一直有效。[示例程序](../OS/user/launch.c) · [派生和等待](fork.md) · [用户接口](../OS/user/api.h)

### 两条入口，共用一个装载器

shell 的 `run` 先接收串口输入的路径。系统调用 `exec` 则从调用者的地址空间复制路径，使用 `a0` 中的用户指针和 `a1` 中的字节数。长度允许 1 到 127 字节，参数中每个字节都属于路径，内核自行补结尾的零。一个尚未兑现的匿名页按定义全部读作零，内核遇到这样的路径字节就可以直接判定失败，连物理页也无需分配。[路径复制](../OS/kernel/paging.c) · [系统调用号](../OS/user/abi.h)

接下来两条入口都调用 `load_program`。它用内核自己的 VFS 文件句柄取得内容，再让 `elf_parse` 检查每个可装载段以及入口地址。即便调用者的四个描述符全在使用，也能运行新程序。路径无效、读盘失败或 ELF 不符合约定时，`exec` 返回 `-1`，调用者从系统调用后继续，原有内存与文件游标仍可用。[共同装载路径](../OS/kernel/trap.c) · [ELF 验证规则](disk-programs.md)

### 验证结束以后才覆盖旧映像

静态 ELF 的装载区最多 16 个页，每个任务在内核内存中预留了相应缓冲区。段边界全部验证通过后，装入与清零便可以完成，即使匿名页池已经用尽。

| 状态 | 成功执行 `exec` 时发生什么 |
| --- | --- |
| 指令与数据 | 撤销旧用户映射，按新 ELF 的权限重新装入。文件字节之后的 BSS 和新栈清零 |
| 匿名区 | 移除本进程的预留区和映射。若另一个进程仍引用某个物理页框，它可以继续使用 |
| 返回现场 | 整数寄存器清零，`sp` 设为用户栈顶，`sepc` 设为 ELF 入口。清除 hart 的 LR 保留，`sret` 从新入口开始 |
| 文件与进程关系 | 已打开的描述符、读取偏移、父子关系和待领取的子进程退出结果继续有效 |

这一版入口采用无参数约定，`a0` 为零。新 ELF 的代码字节刚刚写入 RAM，内核执行 `fence.i` 使本 hart 看见它们。调用者继续使用原来的页表根，新叶项却可能指向不同物理页，因此内核也同步地址翻译。一道屏障处理写入后取指，另一道处理页表变化。[页表构造](../OS/kernel/paging.c) · [指令流同步](../OS/kernel/trap.S) · [根页表安装](../OS/entry.S)

### 父进程先换程序，为什么子进程还能运行

刚完成 `fork` 时，子进程的只读 ELF 叶项可能指向父进程装载区里的物理页。例如双方仍从同一页取指，而父进程准备把第二个 ELF 的代码装到完全相同的虚拟地址。只把父进程的 PTE 改掉还不够，装载器紧接着会往原来的物理页写入新代码。

装载器在覆写父槽的每个物理页前检查子槽同一位置的叶项。若它仍引用这一页，就先将旧内容复制到子槽预留的页，保留原权限并更新子 PTE，再写父进程的新数据。子进程下次取得 CPU 时，原来保存的 `sepc` 仍指向它自己的程序。这个过程中使用的是固定 ELF 装载区，不消耗匿名页池。[物理页保留与重新映射](../OS/kernel/paging.c)
