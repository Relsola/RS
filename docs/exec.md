# 一个进程怎样换成另一个程序

在 `rs>` 输入 `run /launch.elf`。启动程序调用 `user_fork()`，让子进程执行 `user_exec("/hello.elf", 10)`，父进程在原来的程序里调用 `user_wait(child)`。子进程接下来执行磁盘中 `hello.elf` 的入口，输出问候语并退出。父进程领到新程序的退出码 0，于是打印 `launch: child completed`。子进程 ID 从创建到退出一直有效。[示例程序](../OS/user/launch.c) · [派生和等待](fork.md) · [用户接口](../OS/user/api.h)

## shell 与系统调用共用一个装载器

shell 的 `run` 先接收串口输入的路径。系统调用 `exec` 则从调用者的地址空间复制路径，使用 `a0` 中的用户指针和 `a1` 中的字节数。长度允许 1 到 127 字节，参数中每个字节都属于路径，内核自行补结尾的零。一个尚未兑现的匿名页按定义全部读作零，内核遇到这样的路径字节就可以直接判定失败，连物理页也无需分配。[路径复制](../OS/kernel/paging.c) · [系统调用号](../OS/user/abi.h)

有参数的系统调用 `execv` 还从 `a2` 读取参数表的用户地址。三种入口最终都调用 `load_program`。它用内核自己的 VFS 文件句柄取得内容，再让 `elf_parse` 检查可装载段和入口。即便调用者的四个描述符全在使用，也能运行新程序。路径、参数或 ELF 验证失败时，系统调用返回 `-1`，调用者从原来的 `ecall` 之后继续，内存与文件游标仍可用。[共同装载路径](../OS/kernel/trap.c) · [ELF 验证规则](disk-programs.md)

## 验证结束以后才覆盖旧映像

静态 ELF 的装载区最多 16 个页，每个任务在内核内存中预留了相应缓冲区。段边界全部验证通过后，装入与清零便可以完成，即使匿名页池已经用尽。

| 状态 | 成功执行 `exec` 时发生什么 |
| --- | --- |
| 指令与数据 | 撤销旧用户映射，按新 ELF 的权限重新装入。文件字节之后的 BSS 和新栈清零 |
| 匿名区 | 移除本进程的预留区和映射。若另一个进程仍引用某个物理页框，它可以继续使用 |
| 返回现场 | 从零初始化整数现场，再按入口约定设置 `sp`、`a0`、`a1`。`sepc` 指向 ELF 入口，内核清除 hart 的 LR 保留，执行 `sret` |
| 文件与进程关系 | 已打开的描述符、读取偏移、父子关系和待领取的子进程退出结果继续有效 |

新 ELF 的代码字节刚刚写入 RAM，内核执行 `fence.i` 使本 hart 看见它们。调用者继续使用原来的页表根，新叶项却可能指向不同物理页，因此内核也同步地址翻译。一道屏障处理写入后取指，另一道处理页表变化。[页表构造](../OS/kernel/paging.c) · [指令流同步](../OS/kernel/trap.S) · [根页表安装](../OS/entry.S)

## 参数怎样到达新的用户栈

输入 `run /launch.elf /wc.elf "/readme.txt"` 时，`run` 按空格或制表符解析后续参数，成对的单、双引号保留内部空白，`""` 可以传入空字符串。shell 每行最多接收 127 字节。`launch.elf` 收到三个参数，先 `fork`，子进程再调用 `user_execv(argv[1], length, argv + 1)`。新的 `wc.elf` 因而收到两个参数。它按给定路径打开文件，输出换行符数、按 ASCII 空白分隔的词数和字节数。样例文件的输出是 `2 12 64 /readme.txt`。[启动程序](../OS/user/launch.c) · [计数程序](../OS/user/wc.c)

| 入口 | 新程序读到的初始状态 |
| --- | --- |
| `run PATH`、`user_exec(path, length)` | 沿用早期磁盘程序的约定。`sp=0x40004000`，`a0=a1=0` |
| `run PATH ARG ...` | `a0=argc`，包括命令中使用的路径。`a1=argv`，`argv[0]` 是这个路径 |
| `user_execv(path, length, vector)` | 按调用者给出的顺序复制全部字符串，`argv[argc]` 为空指针。传入只含空指针的表得到 `argc=0` 和可读取的空表；直接把表地址传成零会返回 `-1` |

参数最多 8 个，所有字符串连同各自末尾的零共用 256 字节。内核在旧页表仍有效时把字节收进 `ExecArgs`，记录每串的偏移。参数表和字符串都可跨页。尚未兑现的合法匿名页读作零，地址空洞则使调用失败。读取这些字节无需分配物理页，所以一次失败的调用也能保留原来的驻留页数。[参数复制与打包](../OS/kernel/exec_args.c) · [读取用户映射](../OS/kernel/paging.c)

用上面的 `wc.elf` 举例。两个字符串连同结尾的零分别长 8 和 12 字节，放在用户栈顶以下。栈向低地址增长；初始 `sp` 与 `a1` 一起指向 16 字节对齐的指针表首地址，C 函数可以继续向下分配局部变量。

| 新用户栈地址 | 此处内容 |
| --- | --- |
| `0x40003fd0` | `argv[0]`，值为 `0x40003fec` |
| `0x40003fd8` | `argv[1]`，值为 `0x40003ff4` |
| `0x40003fe0` | `argv[2]`，空指针 |
| `0x40003fec` | `/wc.elf\0` |
| `0x40003ff4` | `/readme.txt\0` |

如果只复制旧表里的指针，旧栈与匿名区会在装载新 ELF 时被回收，新程序就会拿到失效地址。先暂存字符串，再用新栈的**用户虚拟地址**重建表，能把这两个地址空间的生命周期分开。测试中的接收程序用汇编在 C 函数序言之前读取寄存器，直接检查栈对齐、指针范围和结尾的空指针。[入口回归](../tests/argv_session.py)

## 父进程先换程序，为什么子进程还能运行

刚完成 `fork` 时，子进程的只读 ELF 叶项可能指向父进程装载区里的物理页。例如双方仍从同一页取指，而父进程准备把第二个 ELF 的代码装到完全相同的虚拟地址。只把父进程的 PTE 改掉还不够，装载器紧接着会往原来的物理页写入新代码。

装载器在覆写父槽的每个物理页前检查子槽同一位置的叶项。若它仍引用这一页，就先将旧内容复制到子槽预留的页，保留原权限并更新子 PTE，再写父进程的新数据。子进程下次取得 CPU 时，原来保存的 `sepc` 仍指向它自己的程序。这个过程中使用的是固定 ELF 装载区，不消耗匿名页池。[物理页保留与重新映射](../OS/kernel/paging.c)
